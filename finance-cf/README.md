# ウィローズグループ CF定期レポート（毎月1日・15日）

WL（ウィローズ）・BU（ウィローズビルド）・CR（ウィローズクラフト）の現金残高を確認し、6ヶ月先までの資金推移を予測します。
CF策の提案もまとめ、Notion「財務ページ」と Slack「#ウィローズグループ財務指標分析」に投稿します。

## 手順

1. **残高の取得**：3社の最新月PDFを読み、`合計` 行の「当期（当月）残高」を月末残高とします。前月繰越の値も前月残高として控えます。
   - 1日の実行時点では前月分のPDFが未アップのことが多くあります（例年3日前後に上がります）。その場合は利用できる最新月を使い、レポート冒頭に「◯月末残高は未アップのため△月末で集計」と明記します。
   - 値は普通預金だけです。定期預金や現金は含めません。
2. **予測シートの取得**：WL と BU を Drive から xlsx でダウンロードします（`download_file_content`。WL には exportMimeType=xlsx を指定）。そのうえで base64 をデコードします。
3. **集計**：`balances.json`（基準月と3社残高、直近5ヶ月の履歴）を作り、次のコマンドを実行します。
   ```
   python3 -I finance-cf/cf_forecast.py --wl wl.xlsx --bu bu.xlsx --balances balances.json
   ```
   - 計画上の基準月残高と実績との差を、以降の月にそのまま乗せます（リベース）。
   - WL は預り敷金・預り家賃を差し引いた「使えるお金」も出します。
4. **判定ライン**（該当したらレポートで赤字扱い）
   - グループ合計 **1.5億円**（「最悪の事態の想定」：販管費2ヶ月分＝1.3億＋α）
   - BU **常時1億円下限**／**期末3億円**（17期財務方針）
   - BU CFトリガー①：**月末現金見込み3億円未満なら新規買付を停止**し、A群の決済着金を確認したら再開
   - WL の「使えるお金」がマイナスになる月
5. **CF策**：判定に引っかかった月と、その原因（大口のPJ返済、建物外注費、仲介入金の減少、納税、賞与）から逆算して提案します。各案に担当・期限を付けます。
6. **投稿**
   - Notion：財務ページ（`3f9f93367ecf80d1b43cea8f003db799`）の配下に子ページ「CFレポート YYYY/MM/DD（M月末基準）」を作成します。あわせて財務ページ上部の「最新サマリー」を差し替え、履歴にリンクを追記します。
   - Slack：`#ウィローズグループ財務指標分析`（`C0C92BT4H61`）にサマリーと Notion リンクを投稿します。

## レポートの型

1. 現在地：3社と合計の月末残高、前月比、直近5ヶ月の推移、計画比（上振れ・下振れ）
2. 半年予測：月別の WL／WL使えるお金／BU／CR／合計と、判定ラインに抵触する月
3. 予測の前提と注意点：既存パイプラインだけで、新規契約・新規仕入・新規融資は入っていません。CF表に入っていない計画物件も明記します。
4. CF策：優先順に、担当・期限付きで提案します。
5. 確認事項：データの不整合や、出どころ不明の入出金
