# 週次・会社重要データ分析レポート RUNBOOK

このファイルは、毎週の自動実行セッションが従う手順書です。Routine（週次トリガー）から
起動されたセッションは、以下を上から順に実行してください。

## 目的
Google Drive上の6つの重要データファイルを読み込み、**前回スナップショットとの差分（前回対比）**を
分析し、結果をSlack DMへ報告する。分析後は新しいスナップショットを保存して次回比較に備える。

## 前提・接続
- Google Drive MCP（`mcp__Google_Drive__read_file_content` 等）と Slack MCP（`mcp__Slack__slack_send_message`）を使用。
  ツールは `ToolSearch` で `select:<tool名>` を指定してロードする。
- 送信先Slack: `config.json` の `slack.target`（自分宛DM）。
- スナップショット: `weekly-company-report/snapshots/latest.json`（前回値）と `snapshots/YYYY-MM-DD.json`（履歴）。

## 手順

### 1. 前回スナップショットを読む
- リポジトリ `ntakeda-eng/-` のブランチ `claude/weekly-company-data-report-hm1py8` から
  `weekly-company-report/snapshots/latest.json` を読む。
- これが「前回値」。存在しない/初回なら前回対比はスキップし、当週を新規ベースラインとする。

### 2. 対象6ファイルを読む（`config.json` の files 参照）
各 fileId を `mcp__Google_Drive__read_file_content` で読み、以下の指標を抽出する。
**粒度は「詳細版」**（担当別・媒体別・物件種別・エリア/予算帯別・月次/週次推移まで）。ざっくりした
全社サマリーだけでは不十分。大きいファイルは Agent（general-purpose）に並列で読ませ、指標をJSONで返させると速い。
抽出キーは `snapshots/latest.json` の各ファイルの metrics キーに揃えること（前回対比が取れるよう同じキー名で）。

| key | 抽出する詳細指標 |
|---|---|
| 16期集計 | 全社の反響/契約/売上/達成率＋**集客区分別(BU/売却推進/買紹介リピート/売り紹介)ごとに反響・契約・売上・目標・達成率**、BUは**物件種別別(新築戸建/MS/中古戸建/売地/コンセプト住宅)の契約・売上**、**直近4ヶ月の月次売上・反響・契約**、反響率 |
| 売買部セールスファネル | ファネル全段(反響→初回接点→案内→商談→申込→成約)の件数と各率、売上高・成約単価・同行、**部署別(下北沢/営業1課/営業2課)の反響・成約・売上・歩留**、**担当別ハイライト(効率上位/下位・ボトルネック)**、**媒体別反響(ポータル/ハウシー/会員登録/紹介/ポリス/自社HP)と質(接点率・歩留)** |
| クラフト顧客管理シート16期 | 年間の反響・完工・受注率・売上・達成率・粗利、当月の売上・完工・受注率・粗利・達成率、**媒体別年間売上(エンド/法人/WL紹介/社員紹介/BU紹介/オフィス/公式サイト/ポリス/GBP)** |
| 会員登録顧客まとめ | 総数、**チャネル別(メール/LINE)**、月別反響、**ランク別(プラチナ/シルバー)**、意向別、**店舗別・担当別**、ファシロ登録・アポ・成約、LINE友だち数 |
| 会員登録反響リスト | 総リード数、**月次・週次推移(直近週の新規)**、**支店別・担当別・予算帯別(1億円以上等)**、プラチナ数、ステータス内訳 |
| Meta物件広告 | 総リード数、**月次・週次推移(直近週の新規)**、**入口別(LP別)**、ファネル(通電→コンタクト→アポ/案内→結果/他決) |

### 3. 前回対比を計算
- 同じ指標キーごとに `当週値 − 前回値` と増減率を出す。
- 特に注目: 売上・契約/成約・反響/リード数の増減、ファネル各段階の変化、達成率・進捗率の動き、当週新規リード数。
- 各ファイルの `as_of`（データ最新日）も前回と比較し、**更新されているか**を必ず明記する
  （as_ofが前回と同じ＝そのファイルは今週更新されていない可能性が高い → その旨を報告）。

### 4. Slackへ報告（詳細版・スレッド形式）
- `config.json` の `slack.target` 宛に `mcp__Slack__slack_send_message` で投稿。
- **1通に詰め込まず、親メッセージ＋スレッド返信で5セクションに分割**する（各5000字以内）:
  - 親: ヘッダ＋① 売買部門・全社（16期集計）
  - 返信(thread_ts=親のmessage_ts): ② セールスファネル ／ ③ クラフト ／ ④ 会員・反響 ／ ⑤ 所見・アラート
- 内訳は**表(Markdown table)**を活用して見やすく。担当別・媒体別・物件種別・予算帯別・月次/週次推移を必ず含める。
- 数字は前回→今週（差分・増減率）の形で。増加は🟢、減少/未達方向は🔴、更新なしは⚪️で示す。
- Slack接続が不安定な場合はツールを再ロードしてリトライする（投稿失敗＝未送信なので重複の心配は少ない）。

### 5. 新スナップショットを保存
- 当週抽出した全指標を `snapshots/YYYY-MM-DD.json`（実行日）に保存。
- 同じ内容で `snapshots/latest.json` を上書き（`is_baseline` は false）。
- 変更をコミットしてブランチ `claude/weekly-company-data-report-hm1py8` に push。
  コミットメッセージ例: `Weekly report snapshot YYYY-MM-DD`。

## レポート雛形（Slack・詳細版スレッド）

**親メッセージ**
```
:bar_chart: *会社データ週次レポート（詳細版）｜YYYY/MM/DD 時点*
_前回(前回実行日) → 今回。🟢増/🔴減/⚪️更新なし。データ時点: 各ファイルのas_of。_

*━━ ① 売買部門・全社（16期集計）━━*
全社: 反響 前回→今週 / 契約 前回→今週 / 売上 前回→今週（達成率XX%）
集客区分別テーブル: 区分|反響|契約|売上|対目標（買紹介/売却推進/BU/売り紹介、前回対比付き）
物件種別内訳(BUの新築戸建/MS/中古戸建/売地/コンセプト住宅)、月次トレンド、反響率
```
**スレッド返信（thread_ts=親）**
```
② セールスファネル: ファネル全段(反響→接点→案内→商談→申込→成約)＋各率、部署別テーブル、担当別ハイライト、媒体別反響と質
③ クラフト(CR): 年間(売上達成率/粗利/反響/完工/受注率)＋当月、媒体別年間売上テーブル
④ 会員・反響: 会員登録まとめ(チャネル/ランク/意向/店舗/担当/進捗) ／ 会員登録反響リスト(月次週次/支店/担当/予算帯/ステータス) ／ Meta物件広告LP(入口別/週次/ファネル)
⑤ 所見・アラート: 増減の大きい項目・未達・停滞・好調を🔴🟡🟢で4〜7点。前回更新がなかったファイルもここで注意喚起
```

## 注意
- ファイルの列構成やタブは将来変わりうる。指標が取れない場合はそのファイルを「取得失敗」として
  レポートに明記し、他ファイルの報告は継続する（1ファイルの失敗で全体を止めない）。
- 個人情報（顧客の氏名・連絡先）はレポートに含めない。集計値・傾向のみ報告する。
